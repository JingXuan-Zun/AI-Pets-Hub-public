AI Desktop Pet 测试包更新摘要与简易 SOP

测试包版本：build-20260905-172144
正式测试文件：release/build-20260905-172144/AI-Desktop-Pet-20260905-172144.exe


一、本次主要更新

1. 表情包回复与回复方式占比

- 新增“回复方式占比”设置，可分别调整图片表情、颜文字、Emoji 的权重。
- 新增“启用表情回复”开关；关闭后桌宠仅使用文字回复。
- 图片表情包库未选择、没有已审核图片或图库不可用时，图片实际占比自动为 0，不会错误发图。
- 内置 Emoji 和颜文字目录，按开心、伤心、疑惑、关心、打招呼等语义匹配；内置内容只读，不能被删除或修改。
- 增加近期去重设置，减少连续重复使用相同表达方式。

2. 图片表情包库与分类

- 支持“应用托管库”和“外部目录库”两种模式。
- 应用托管库可导入、创建分类、移动和删除应用管理的图片。
- 外部目录库仅读取用户原文件；移动只调整应用内分类，移除只让应用停止使用图片，绝不删除或修改原文件。
- 默认提供“开心”“伤心”一级分类；用户可建立更多分类，并编写分类语义说明。
- 支持导入已按一级分类整理的表情包根目录。

3. 批量审核处理区

- 新导入、重新扫描发现或移动分类后的图片均进入“待审核”。
- 只有点击“通过审核”的图片才可被桌宠用于回复。
- 支持“全部 / 待审核 / 已审核 / 文件已失效”筛选与数量统计。
- 支持批量选择、全选、通过审核、退回待审核、移动到其他分类。
- 托管库显示“删除”；外部目录库显示“从应用图库移除”。
- 批量操作会显示成功数量、失败明细，并提供 60 秒撤销入口。
- 删除分类后保留的图片会进入“待重新归类”，必须移到新分类并审核后才能再次使用。

4. 聊天、多人系统与视觉能力

- 更新多人聊天的并行生成、话题推进、注意力判断、记忆候选与关系演化控制；自动长期记忆、自动关系演化和自动小团体演化默认关闭。
- 新增游戏陪玩设置入口，用于游戏观察频率与角色回应配置。
- 增加 2D 视频角色的渲染支持。

5. Agent Runtime

- 设置中可选择默认 Native Runtime，或配置 DeepSeek Harness 外部 Python SDK。
- DeepSeek Harness 当前可检测 SDK、检查更新和准备受控 Profile。
- 该外部运行时的真实工具执行仍处于安全锁定状态，不应作为本轮测试的正式执行能力。


二、测试包隐私状态

- 包中不包含打包电脑的聊天记录、记忆、个人设置、用户头像、表情包索引或用户表情库。
- 本地 3D 模型库不会进入可分享测试包。
- 测试包只带内置系统 Emoji/颜文字目录；每位测试者首次运行后会在自己的电脑上创建自己的本地数据。


三、测试人员操作 SOP

步骤 1：获取与启动

1. 获取 AI-Desktop-Pet-20260905-172144.exe。
2. 双击运行 portable 文件。
3. 若 Windows SmartScreen 弹出提示，测试人员应按自身安全策略决定是否继续；来源不明时不要运行。
4. 关闭应用时，须在托盘菜单中选择退出，确认没有残留桌宠进程。

步骤 2：基础聊天测试

1. 打开私聊，发送普通问候、关心、安慰、疑惑等文本。
2. 确认桌宠能正常返回角色回复，聊天记录正常显示。
3. 如出现“允许 / 拒绝 / 等待确认”的 Agent 审批卡，请不要点击“允许”；点击“拒绝”或“终止”，记录触发前的完整用户文本并反馈。

步骤 3：表情回复设置测试

1. 打开控制中心：高级 -> 表情包。
2. 开启“启用表情回复”。
3. 分别调整图片表情、颜文字、Emoji 权重，点击底部“保存”。
4. 未导入并审核图片时，确认图片表情的实际可用占比为 0，桌宠不会尝试发送图片。
5. 将颜文字或 Emoji 权重调高后，多轮聊天观察是否出现合理且不过度重复的文字表情。

步骤 4：应用托管库测试

1. 在“图片表情包库”选择“应用托管库”。
2. 创建或选择一个一级分类，例如“开心”。
3. 导入几张 PNG、JPG、GIF 或 WEBP 图片。
4. 打开批量处理区，确认新图片显示为“待审核”。
5. 选中图片，点击“通过审核”；确认状态变为“已审核”。
6. 再进行聊天，确认图片仅在语义合适时作为回复候选；它不应每句强制出现。
7. 选中图片并“移动到…”另一分类；确认图片自动退回“待审核”。
8. 测试“退回待审核”“删除”和“撤销（60 秒内）”。

步骤 5：外部目录库测试

1. 准备一个测试用文件夹，内部按“开心”“疑惑”等一级文件夹存放测试图片。
2. 在应用中选择“外部目录库”，选择该测试文件夹。
3. 重新检查图库，确认图片被发现且默认处于待审核。
4. 通过审核部分图片，确认可用数量发生变化。
5. 使用“从应用图库移除”，确认应用停止使用该图，但 Windows 文件夹中的原图仍然存在。
6. 重新检查图库后，确认已从应用图库移除的图片不会自动恢复为可用候选。

步骤 6：多人、陪玩与 Runtime（可选）

1. 多人系统：检查多人聊天、话题推进和设置开关是否正常展示；不要将默认关闭的自动记忆/关系演化视作故障。
2. 游戏陪玩：确认高级设置中可以进入陪玩页面；若没有配置视觉模型或游戏窗口，功能可能不会产生实际回应。
3. DeepSeek Harness：仅测试 SDK 检测、更新检查、受控 Profile 准备和错误提示；不要输入或分享他人的 API Key。

五、当前已知限制

1. 普通角色扮演文本若同时包含“坐”等动作词和角色指代，可能被误判为桌宠动作指令，进而显示 Agent 审批卡；遇到时请拒绝或终止并反馈文本。
2. DeepSeek Harness 当前是 SDK 适配与检测阶段，工具执行仍被安全锁定。
3. Windows 签名证书尚未配置，测试包未进行代码签名；部分电脑可能显示 SmartScreen 警告。
