表情包批量处理区修改建议

一、目标

将批量处理区改造成以“待审核队列”为核心的工作流：图片先进入所属一级分类，只有经用户审核通过后，才能成为桌宠自动回复的候选图片。

用户只需要理解“开心、伤心、疑惑”等一级分类；审核状态由应用索引管理，不要求用户在资源管理器中维护额外的工作流文件夹。


二、现状与需要解决的问题

当前批量处理区提供“确认语义、待审核、排除、移动到…、移动、删除”等操作。

存在的问题：

1. “确认语义”的真实效果是允许图片参与桌宠回复，文案不够直观。
2. “排除”和“删除”在托管库中容易被理解为同一件事；而外部目录下的“删除”实际上不能删除用户原文件，含义不一致。
3. “移动到…”负责选择目标，“移动”负责提交，交互步骤重复。
4. 当前仅有归类版本筛选，缺少用户最常用的“待审核 / 已审核”队列视图。
5. 图片移动到一个有语义说明的分类时，现有实现可能直接设为已确认，绕过用户审核。
6. 批量操作后缺少明确结果说明、失败项说明和撤销机会。


三、最终操作栏

将现有操作栏：

    确认语义｜待审核｜排除｜移动到…｜移动｜删除

调整为：

    通过审核｜退回待审核｜移动到…｜删除

具体规则：

1. “确认语义”改为“通过审核”。
   该操作将选中图片的状态改为“已审核”，图片从此可以参与桌宠自动回复。

2. “待审核”改为“退回待审核”。
   它只用于已审核图片被发现归类不正确、分类语义改变，或用户希望重新审核时。

3. 删除“排除”按钮。
   对于应用托管库，用户可直接使用“删除”。
   对于外部目录库，使用“从应用图库移除”替代“删除”，该动作不会修改或删除用户原文件，只会使应用不再把图片纳入图库与自动回复候选。

4. 合并“移动到…”和“移动”。
   用户点击“移动到…”后，选择目标一级分类即执行移动，不再保留独立的“移动”确认按钮。
   可在执行前显示一次简短确认，或执行后提供“撤销”入口。


四、审核状态设计

不在一级分类下创建“待审核”“已审核”实体文件夹。

文件目录保持为：

    表情包根目录/
      开心/
        开心1.png
        开心2.webp
      伤心/
        伤心1.gif

每张图片的审核状态只保存于应用索引：

    待审核（needs-review）
    已审核（accepted）
    从应用图库移除（内部可保留 excluded 状态，仅用于外部只读图库）

不建立审核子文件夹的原因：

1. 用户在资源管理器中只面对语义分类，不需要理解审核工作流。
2. 审核动作不搬动文件，避免路径变化、同名冲突及索引失配。
3. 外部目录是只读引用，应用不能为其创建或移动“已审核”子目录。
4. 现有索引已经保存图片状态，沿用该机制成本低，且能同时覆盖托管库与外部目录库。


五、不可绕过的审核规则

1. 用户拖入或导入的新图片，默认状态必须是“待审核”。
2. 重新扫描外部目录时新发现的图片，默认状态必须是“待审核”。
3. 图片移动到任意一级分类后，默认状态必须是“待审核”。
4. 只有用户执行“通过审核”后，图片才能被桌宠选作回复图片。
5. 一级分类的名称或语义说明发生变化后，该分类全部可用图片自动退回“待审核”。
6. 待审核、从应用图库移除、原文件已失效，以及分类语义版本不匹配的图片，均不得参与桌宠自动回复。
7. 旧数据中已标记为“排除”的图片不可自动恢复为可用状态；应显示为待处理，由用户重新决定审核或从图库移除。


六、批量处理区界面

在图片网格上方增加状态筛选与数量统计：

    全部 12 ｜ 待审核 8 ｜ 已审核 4 ｜ 文件已失效 0

默认展示“待审核”，使用户导入图片后能立刻看到需要处理的队列。

图片卡片统一显示：

    待审核 · 分类语义 v2
    已审核 · 分类语义 v2
    文件已失效

“归类版本”保留为高级筛选，用于检查某一历史分类版本；它不能替代审核状态筛选。


七、两种图库模式下的批量操作

1. 应用托管库

    通过审核：更新索引状态为已审核。
    退回待审核：更新索引状态为待审核。
    移动到…：移动应用托管的图片文件到目标一级分类，并将状态改为待审核。
    删除：经二次确认后删除应用托管的图片文件及对应索引记录。

2. 外部目录库

    通过审核：只更新应用索引状态，不修改原文件。
    退回待审核：只更新应用索引状态，不修改原文件。
    移动到…：只修改应用索引中的分类归属；不得移动外部原文件。
    从应用图库移除：保留原文件，但永久不让应用将该图片作为回复候选；重新扫描也不能自动重新启用它。


八、批量操作反馈

每次完成操作后，应显示结果提示：

    已通过审核：8 张；桌宠现在可使用这些图片回复。
    已移动：5 张至“疑惑”；这些图片已转为待审核。
    已删除：3 张托管图片。
    已从应用图库移除：2 张；用户原始外部文件未修改。

要求：

1. 删除托管图片必须二次确认。
2. 移动、审核、退回待审核应提供短暂的“撤销”入口。
3. 批量操作部分失败时，必须显示成功数量、失败数量与失败原因，不得只显示笼统的失败提示。


九、实施优先级

P0：修正分类名输入校验和异常历史分类名称的修复机制。
P0：将“移动后可能自动通过审核”改为“移动后一律待审核”。
P1：改造操作栏文案，合并“移动到…”与“移动”，移除“排除”按钮。
P1：为托管库和外部目录库分别提供“删除”与“从应用图库移除”。
P1：新增“全部 / 待审核 / 已审核 / 文件已失效”状态筛选及数量。
P2：补充批量操作结果、失败明细和撤销机制。
P2：保存审核时间、操作来源、操作人和目标分类等审计记录。


十、验收标准

1. 新导入图片不会在未审核状态下参与桌宠回复。
2. 用户通过审核后，图片可以参与回复；退回待审核后立即不可用。
3. 图片移动到任何分类后均处于待审核。
4. 托管库删除会删除应用管理的图片；外部库“从应用图库移除”绝不修改原文件。
5. 用户能一眼看到待审核数量，并能仅查看待审核图片。
6. 页面中不再出现“排除”“移动到… + 移动”的重复交互组合。
7. 分类语义变更后，旧审核结果自动失效，用户必须重新审核。
8. 重新扫描不会让已从应用图库移除的外部图片自动重新成为回复候选。
