## 设计原则

1. **她得像她自己。** 角色的说话方式、称呼、性格写在人格和知识库里，代码只负责把它们送到模型面前，不往回复里塞固定话术。
2. **你说了算。** 记忆要你批准才写入；看屏幕要你同意；会改动东西的操作先开口问你，撤不回的（发送、删除、付款、关闭程序、覆盖文件）每次都问。
3. **数据留在本机。** 聊天、记忆、角色和配置都在用户自己的电脑上；密钥用系统加密保存。
4. **一个循环、一个决策者。** 聊天和办事走同一个对话循环，由模型在预算内决定下一步，不让多个规划器互相打架。
5. **能验证才算做完。** 桌面操作做完要再看一眼，确认结果真的出现了。

## 整体结构

```text
┌────────────── Electron 主进程（electron/）──────────────┐
│ 配置存储 · MCP 客户端 · 她的浏览器 · 文件服务 · 窗口/图标/输入 │
│ QQ(SnowLuma) / 微信 · 软件更新 · 诊断导出 · 命令与路径防护     │
└───────────────▲──────────────────────────▲──────────────┘
                │ 只接受应用自带页面的 IPC   │
   ┌────────────┴───┐  ┌──────────────┐  ┌─┴────────────┐
   │ 桌宠窗口        │  │ 聊天窗口      │  │ 设置中心      │
   │ 角色运行时、对话  │  │ 消息、任务卡片 │  │ 各项设置、插件 │
   │ 循环、语音       │  │ 互动对话      │  │ 市场、版本列表 │
   └────────────────┘  └──────────────┘  └──────────────┘
          React 19 + TypeScript + Vite（src/）
```

- 三个窗口各自独立，通过主进程保存的同一份配置和 IPC 共享状态。对话循环、语音和工具都跑在桌宠窗口里，聊天窗口只负责显示和输入。
- 主进程（`electron/`）提供界面做不到或不该做的事：读写文件、启动程序、操作窗口和桌面图标、连接 MCP 服务器、控制她的浏览器等。大致一个服务一个文件，按 `xxxService.cjs` / `xxxIpc*.cjs` 组织。
- 入口是 `electron/bootstrap.cjs`：它先决定用安装包自带的代码还是已下载的更新，再加载 `electron/main.cjs`（见[软件内更新](#软件内更新)）。

## 对话循环：聊天和办事是同一件事

代码：`src/agent/conversation/`

用户说一句话，模型的回复里可以直接调用工具；工具结果再交给模型，直到它不再调用工具、只回答为止。核心在 `conversationToolStream.ts` 的 `streamConversationWithTools`：

1. 请求一轮模型，边收边把文字流给界面和语音。
2. 这一轮如果调用了工具，就执行（`conversationTools.ts` 的 `runConversationToolCalls`）：不需要确认的工具并行跑，需要确认的按顺序一个一个问。
3. 结果加进下一轮的消息，继续。轮数、步数、时长都有上限。

**工具从哪来。** `conversationToolProviders.ts` 是唯一的注册入口：桌面操作、文件、窗口移动、桌面图标、能力清单、插件、MCP、技能、联网搜索等，按当前角色和设置拼出这一轮可用的工具（约 80 个）。

**任务卡片。** 一用到工具，聊天里就出现一张卡片（`src/components/chat/runController/conversationTaskCard.ts`），一步一行，写着在做什么、成没成功；确认也在卡片上回答。卡片的文字同时是一条“任务记录”，留在对话历史里，所以她之后知道做过什么、哪件没做完。

**几种结束方式。**

| 情况 | 卡片上写 |
| --- | --- |
| 做完了 | 已完成 |
| 用户点了终止 | 已终止 |
| 用户插话，这一轮被掐断 | 被新的消息打断，还没做完 |
| 遇到要登录 / 激活的软件，或连着失败 3 步（`desktopDeadEnds.ts`） | 卡住了，停下来问你怎么办 |
| 步数用完 | 步骤太多，先停下了 |

**请求怎么拼（省钱）。** 模型服务对“和上次请求开头相同的部分”按缓存价收费。所以系统消息只放不变的人格和规则；每轮会变的内容（选中的记忆、待办、后台任务、当前时间、搜索结果）放在聊天记录后面；聊天记录超出窗口时一次移走 20 条，开头尽量保持不变。见 `src/services/geminiPromptService.ts` 的 `buildCharacterReplyStableInstruction` / `buildCharacterReplyTurnContext` 和 `limitHistoryForPrompt`。每次请求的缓存命中会记一行日志 `prompt cache usage`。

## 桌面操作：看、做、再看一眼

代码：`src/agent/loop/`、`src/agent/conversation/conversationDesktopTools.ts`

- **分层观察**（`observationTiers.ts`）：先看便宜的（窗口列表、UI Automation 结构），不够再做区域 OCR，最后才用视觉模型。界面元素带编号和屏幕坐标，模型用编号点。
- **动作**：点击、输入、按键、滚动、拖动、启动程序、切换 / 移动 / 关闭窗口。每次动作后自动重新读窗口，把“变化了什么”和新的元素清单还给模型。
- **找窗口**：按标题和进程名匹配；中文应用名（“记事本”）会补上英文进程名 / 标题词（`electron/appLauncher/windowsAppChineseAliases.cjs`）。
- **管理员窗口**：以管理员身份运行的软件，通过一个只在本机、一次性授权的辅助进程完成点击和输入（`electron/elevatedInputBroker.cjs`），桌宠本身不用管理员权限。
- **桌面图标**：可以只整理某一块屏幕，或把一个图标放到指定屏幕的指定角落；先出预览，确认后才挪。

## 确认与权限

- 只读的操作直接做；会改动东西的先问。一个任务里点击、输入这类操作在你允许任务后连续执行（`src/agent/loop/loopApproval.ts`）。
- 撤不回的每次都问：发送、删除、付款、关闭程序、覆盖文件；在聊天软件、浏览器里打字后按回车也会问（可能就是“发送”），在记事本这类编辑器里不问。
- 角色会用自己的声音问，用户可以说“好 / 不要”、在卡片上点，也可以在 QQ / 微信里回。“今天都允许”覆盖当天的一般操作，撤不回的仍然每次问（`src/agent/approval/dailyApproval.ts`）。
- 用户拒绝过一次，当天的授权立即失效。

## 能力清单和设置清单

- **能力清单**（`src/platform-capabilities/`）：提醒、待办、天气、角色和显示设置、数据备份、知识库等“平台能力”，每个能力声明参数、说明和风险等级（`read` 只读 / `personal` 只影响自己的清单 / `change` 改设置要确认）。对话循环把它们当工具用。
- **设置清单**（`src/settings-manifest/`）：一个设置项只声明一次（名字、取值、会不会改变她的行为），设置页和角色共用。她能用 `settings.find / set / open_page` 查找、修改设置，或帮你打开对应的设置页。

## 插件系统

代码：`src/plugins/`、`electron/pluginPackageService.cjs`、`services/plugin-market/`；格式见 [`docs/plugin-format.md`](./plugin-format.md)

| 种类 | 是什么 |
| --- | --- |
| 原生插件 | 随应用提供：ComfyUI 画图、QQ 连接、微信连接、开发助手 |
| 技能（SKILL.md） | 一份做事的说明书，她按需读取再照着做 |
| MCP 工具 | 标准 MCP 服务器（stdio），主进程负责启动和调用 |
| 插件包 | 带 `plugin.json` 的压缩包，可以包含技能、MCP 配置和设置项 |

- **插件市场**：Cloudflare Worker + R2 + D1（`services/plugin-market/worker.mjs`）。投稿先人工审核才公开；安装前列出要哪些权限。
- **按角色开关**：每个插件可以只给某几个角色用。
- **发链接装插件**（`pluginLinkInstall.ts`、`electron/pluginLinkInspect.cjs`）：只读 GitHub 上的 `plugin.json`、`SKILL.md`、`README.md`、`package.json` 判断是什么、要什么环境，告诉用户“没经过审核”，同意了才装，每次都问。
- **MCP 只读工具**：服务器声明 `readOnlyHint` 的工具不弹确认；调用前按工具的输入定义修正参数类型。
- **插件设置**：`plugin.json` 里可以声明设置项，设置页自动生成，她也能用设置清单改。

## 她自己的浏览器

代码：`src/plugins/herBrowser.ts`、`electron/browserSearch*.cjs`、`electron/herBrowserFocusGuard.cjs`

应用会启动一个独立资料夹的 Chrome（和用户的浏览器、账号完全分开），开着调试端口；chrome-devtools MCP 插件连到它上面，她就能打开网页、点按钮、填表、截图。

- 用户在插件页点“打开她的浏览器”，替她登录她自己的账号。
- 她切换标签页时浏览器会被带到前台；主进程会把焦点还给用户原来的窗口（只在被她的浏览器抢走时）。浏览器加了“被挡住也照常绘制”的启动参数，所以在用户窗口后面也能截图。

## 记忆与人格

代码：`src/neural-memory/`、`src/character-memory/`、`src/character-graph/`

- **记忆提议**：聊天中出现值得记住的事，角色提出“要我记住吗？”，用户批准、修改或拒绝；没有批准什么都不写入长期记忆。
- **“关于你”共享记忆**：对一个角色说“帮我记住”，所有角色都知道；“忘掉”先确认再删。
- **对话摘要**：移出聊天窗口的旧消息按批写进过往摘要（`conversationSummary.ts`），长对话不失忆。
- **神经人格**：把角色的长期信息组织成可浏览、可维护的图谱；新的“神经”只来自角色提议、用户批准的记忆。
- **知识库**：每个角色有自己的知识库（规则、简介），还有所有角色共用的全局知识库。

## 角色运行时

代码：`src/pet-runtime/`

| 形态 | 实现 |
| --- | --- |
| 2D 图片 / 视频 | 序列帧、视频文件夹轮播，按情绪选片段 |
| Live2D | PixiJS + `pixi-live2d-display` + Cubism Core |
| VRM / GLTF / FBX | Three.js + React Three Fiber + `@pixiv/three-vrm` |
| MMD | PMX / PMD 模型、VMD 动作，ammo.js 刚体物理 |
| Unity | 通过 Unity Bridge 协议驱动外部 Unity 运行时 |

待机、拖拽、点击互动和情绪表情由运行时统一调度。互动对话（视频通话）在聊天窗口里用同一套渲染器画角色，通话时桌面上的这个角色暂时隐藏。

## 语音

代码：`src/voice/`；语音包格式见 [`docs/voice-pack-format.md`](./voice-pack-format.md)

- **播报**：GPT-SoVITS（本地，轻量包或训练包）、浏览器语音、OpenAI / Gemini 语音接口；长回复按完整句子分组，边合成边播放。
- **识别和唤醒**：本地语音识别；每个角色有自己的唤醒词，按发音匹配。
- **语音运行环境**：首次使用时安装到 exe 旁边，位置记在用户数据里，移动 exe 也找得到。

## 手机连接：QQ 和微信

代码：`src/qq-bridge/`、`src/weixin-bridge/`；QQ 设置见 [`docs/qq-bridge-setup.md`](./qq-bridge-setup.md)

- **QQ**：通过 SnowLuma（OneBot v11）连接一个小号；文字、图片、表情、语音双向。语音用当前角色的声音合成，长回复分段合成再拼起来。
- **微信**：官方 ClawBot 通道，手机扫码登录；只能发文字、图片、视频、文件，所以她的语音以短视频发送。
- 两边都可以回答确认（“好 / 不要”）；消息按“她这句话说完了”的事件转发，不靠猜顺序。

## 后台任务和事件

- **后台任务**（`src/agent/background/backgroundTasks.ts`）：画图这类慢活放到后台，她继续聊天，做完主动告诉你，也会发到 QQ / 微信；一次只做一件，可以取消。
- **事件流**（`src/events/appEvents.ts`）：任务开始 / 进度 / 结束、“她的回复说完了”等事件；手机转发、任务提示条都订阅它。

## 软件内更新

代码：`electron/bootstrap.cjs`、`electron/appUpdate*.cjs`、`scripts/build-app-update.mjs`

- 发布时生成一份 **ed25519 签名** 的版本清单（`latest.json`）和只含改动文件的更新包；应用里只有公钥。下载源：Cloudflare R2 为主，GitHub Releases 备用。
- 下载后按清单逐个核对文件，解压到用户数据的 `app-updates/<版本>/`。
- `bootstrap.cjs` 启动时决定用哪个版本；新版本启动不起来就退回上一个能用的版本，并告诉用户。
- “底座”（Electron 版本 + 依赖）变了的版本只能下载完整安装包。

## 隐私与安全

- **凭据**：API Key 用 Electron `safeStorage` 加密；加密不可用时拒绝保存，不退回明文。
- **IPC**：主进程只接受应用自带页面发来的 IPC（`electron/ipcSenderGuard.cjs`）。
- **工具输出是数据**：网页、文件、工具返回的内容只当数据，不当指令。
- **碰不到的地方**：文件工具和命令碰不到应用自己的配置、密钥、聊天记录和浏览器登录数据（`electron/sensitivePathPolicy.cjs`、`electron/commandPathGuard.cjs`）。
- **诊断导出**：日志里说的话、角色名、窗口标题、工具参数会换成“<略>”，路径里的用户名换成 `<user>`（`electron/diagnosticsExport.cjs`）。
- 安全问题请通过 GitHub 私密漏洞报告联系。

## 测试

- `scripts/*-smoke.*`：几百个冒烟检查，按模块命名，用 `npx tsx` 或 `node` 直接运行。
- `npm run lint`：TypeScript 类型检查。
- **任务基准**（`scripts/benchmark/`）：开发版带调试端口启动后，`bench-run.cjs` 发一句话、自动回答确认、计时；`desktop-icons.cjs` 给桌面图标拍快照 / 还原，做桌面整理测试时保证主屏不被动到。

## 接下来

- 互动对话：口型和表情跟着她说的话动，她也能自己提出“我们视频吧”。
- 插件进程宿主：任意语言写的插件在独立进程里运行，权限更清楚。
- 导入别的桌宠平台的角色（先从 VPet 的角色动画开始，只导入用户自己装过的）。
- 让角色自己上网学习、慢慢长出自己的样子；学到的东西要用户同意才记下。
- 让神经人格、长期记忆和角色关系更深地参与日常对话；多个角色互通近况。
